# T010 Leveling Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Convert picked-up experience into levels and a lossless level-up queue, freezing simulation in `LEVEL_UP` until T011 consumes every queued choice.

**Architecture:** A focused `LevelSystem` owns threshold conversion and pending choices. `GameStateManager` adds controlled entry/exit transitions, while `GameWorld` processes experience after pickup and enters `LEVEL_UP` only after the triggering fixed step has advanced its clock. T010 exposes queue count in the immutable HUD snapshot but leaves choice UI to T011.

**Tech Stack:** Existing native JavaScript ES modules, Vitest, fixed-step GameLoop, GameWorld, no new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-12-t010-leveling-design.md`

## Global Constraints

- SRS threshold: `6 + 4 × (current level − 1)` experience.
- Excess experience carries forward; each crossed threshold increments one level and queues one choice.
- A queued level choice freezes gameplay time and simulation until consumed.
- Reset restores level 1, experience 0, and an empty queue.
- Exact integer threshold math uses bounded cumulative calculations; values outside the safe Number representation are rejected atomically, without a gameplay level cap.
- `GameWorld.reset()` rejects `LEVEL_UP` before mutation so it cannot discard choices while leaving the game frozen.
- Do not add upgrade effects, choice cards, a level cap, experience modifiers, or dependencies in T010.
- Existing MENU, PLAYING, PAUSED, focus-loss and restart behavior remains intact.

## Review Focus

- Threshold edge and multilevel input: test below, exact, overflow, and distinct thresholds crossed in one pickup.
- Invalid player level/experience: test that unsafe level or non-finite/negative experience is rejected without partial mutation.
- Numeric precision/performance: test an unrepresentable threshold, a large supported experience, and prompt rejection beyond the representable level range.
- Invalid state transitions or queue consumption: test that pause/resume/Escape paths cannot bypass a pending choice.
- Completion notification ordering: test that state listeners see a zero pending count when the last choice restores PLAYING.
- Fixed-step transition timing: test the threshold-crossing step counts once and later time/steps freeze.
- Restart after a pending level-up: test player values, queue, and state return to a clean new run.
