# T017 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace flat placeholder shapes with original, readable, restrained pixel art and fixed-time visual feedback without changing gameplay.

**Architecture:** Freeze sprite matrices in a small presentation config and draw them through the existing Canvas pipeline. Add bounded fixed-step particles sourced from existing world events and keep all UI polish in CSS/DOM.

**Tech Stack:** Native JavaScript ES modules, Canvas 2D, CSS, Vitest, Vite; no new dependencies or external assets.

**Spec:** `docs/superpowers/specs/2026-10-12-t017-pixel-art-design.md`

## Global Constraints

- Preserve all SRS gameplay values and rules.
- Use fixed-step effective time for animation and particles; pause, LEVEL_UP, terminal results and reset semantics remain intact.
- Do not use per-render random numbers, external downloads, new dependencies, or collision geometry changes.
- Keep clipping, logical viewport, DPR scaling and readable UI intact.

## Review Focus

1. Sprite bounds stay within their gameplay entity sizes and render with camera offsets/clipping.
2. Sprite/particle animation freezes across PAUSED/LEVEL_UP/VICTORY/DEFEAT and clears on reset.
3. Particle count remains bounded under a 100-enemy death burst scenario; no per-bullet/per-blade particle storm.
4. Type-specific sprite patterns have a neutral fallback for unknown ids.
5. Decorations remain visual-only and add no map collision/obstruction or HUD overlap.
