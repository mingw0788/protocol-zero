# T014 Enemy Waves Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add EN-02/EN-03 and deterministic, configurable wave profiles while preserving the confirmed enemy values, timing milestones, spawn safety, and 100-normal-enemy cap.

**Architecture:** `WaveSystem` is a stateless lookup over effective battle time and returns an immutable profile. `GameWorld` selects the profile for the end of each active fixed step; `SpawnSystem` uses that profile to schedule and weight-select normal enemy types, then performs radius-aware safe placement. `EnemyRenderer` already consumes entity color/radius, so no rendering interface change is needed.

**Tech Stack:** Native JavaScript ES modules, Canvas 2D, Vitest, Vite; no new project dependencies.

**Spec:** `docs/superpowers/specs/2026-10-12-t014-wave-system-design.md`

## Global Constraints

- Keep SRS enemy HP, speed, contact damage, XP, 60/120/180/240/270-second milestones, 32-world-pixel viewport clearance, and 100 active normal-enemy cap.
- Use only effective game time; MENU, PAUSED, LEVEL_UP, player-death freeze, and reset follow existing GameWorld behavior.
- Keep wave profiles and enemy configuration frozen; no upgrade RNG coupling, dependencies, Boss behavior, wave UI, or V1 scope expansion.
- D-035 values are configurable first-tuning values, not new fixed gameplay commitments.
- Use TDD; run the full suite, production build, `git diff --check`, and a controlled browser check; report only observed evidence.

## Review Focus

- Exact boundary at 60/120/180/240/270 seconds selects the next frozen profile; just-before selects the previous one.
- Variable enemy radius is used for world bounds, viewport clearance, and player separation at each spawn location.
- A mixed wave samples only positive weights; a single-type opening consumes no additional random draw.
- Boss-category entities do not count toward the normal-enemy cap; cap tokens are consumed without delayed burst.
- Reset and pause leave effective time as the sole wave clock; death drops, XP, and rendering remain on existing paths.
