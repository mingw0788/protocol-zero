# T018 音效系统与设置设计

**日期：** 2026-10-12  
**依据：** SRS §2.1、FR-001、FR-018；SDD §1/§11.8；既有 GameWorld/UIManager 生命周期  
**状态：** 已按连续开发授权实施并验收；报告见 `docs/task-report-T018.md`

## 意图与边界

给单机战局提供简洁、可关闭、可调音量的短音效，满足主菜单音效开关与浏览器播放限制要求。保留已存在的运行期音效开关；新增音量滑杆、音频服务和清晰的事件接线。SRS 只要求基础音效，本任务不加入背景音乐、不加载音频文件、不增加依赖，也不更改战斗规则或时间。

## 结构与事件

- `AudioManager` 作为表现层服务，通过 `GameWorld.subscribeAudioEvent()` 接收冻结的语义事件：脉冲枪发射、普通敌人死亡、玩家受伤、玩家死亡、升级选择、胜利和失败。
- `GameWorld` 只在现有逻辑事件确实发生时发送声音事件；订阅只注册一次，重开保留订阅但不补发历史事件。单次升级、死亡和终局仍受现有规则约束。
- `AudioManager` 在用户点击“开始游戏”或重新打开音效时，惰性创建/恢复 `AudioContext`。使用 Web Audio oscillator/gain 合成短音，无静态音频素材；浏览器不支持、创建失败、上下文恢复失败时静默降级，游戏逻辑继续。
- 单声部短音调按事件类别配置频率、波形、时长与音高曲线。最多同时保留 8 个有效音声部；超额新事件静默丢弃，避免密集击杀时声音堆积。事件音使用单一主增益节点做全局音量和静音。
- 音量范围 0–100%，默认 65%；静音只影响输出，不改变音量值。重开保留本次页面运行期设置，停止 Game 时解除世界订阅并释放音频上下文。持久化归 T019。
- UI 在主菜单提供带中文标签的范围滑杆，现有切换按钮继续提供明确开/关状态和 `aria-pressed`。不在战斗 HUD 增加设置控件。

## 验收

- 单元测试覆盖惰性创建、音量映射、静音、事件音调参数、同时发声上限、API 缺失/异常降级、停止释放和世界事件只发送一次。
- UI 测试覆盖滑杆语义/默认值、变化更新、静音与音量互不覆盖、重开/回菜单保留运行期设置。
- 完整测试 47 个文件 / 376 项通过，生产构建 58 模块通过；Chromium 实测用户交互后 AudioContext 进入 running，受控战斗创建音声部，35% 音量映射约 0.35，640×360 控件可见，控制台错误/警告 0/0，外部资源数组为空。完整记录见 T018 报告。

## 实施解释

- D-015 采用最小 V1 范围：不加背景音乐。SRS 与 FR-018 明确要求基础音效，背景音乐仅出现在开发计划的早期草案，加入它会扩展体验与资源范围。
- 音效音量是展示偏好，不进入 GameWorld，不影响固定步、暂停或结算数据；T019 可保存/恢复该偏好。
