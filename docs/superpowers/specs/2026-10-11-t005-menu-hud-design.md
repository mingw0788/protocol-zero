## 1. 目标与范围

交付可从标题主菜单开始的可操作原型，并提供真实数据驱动的战斗 HUD 和安全暂停流程。保留原生 JavaScript、HTML/CSS、Canvas 2D 的既有架构，不增加 UI 框架或运行时依赖。

本任务包含：

- 首次打开停留在标题主菜单；点击“开始游戏”后才进入 PLAYING。
- 操作说明、运行期声音开关、战斗 HUD、暂停界面及返回主菜单确认。
- 为 HUD 建立只读真实状态快照；界面不持有或修改战斗数据。
- 补齐暂停后返回主菜单的合法状态迁移，并在返回或开局时重置本局。

本任务不包含：

- 敌人、伤害、击杀、经验拾取、升级或武器攻击逻辑。
- 升级选择 UI、Boss UI、胜负结算或完整重开流程；这些由后续任务负责。
- Web Audio 播放能力（T018）和声音偏好持久化（T019）。本任务的声音开关只保存本次页面会话中的偏好状态。
- 背景音乐或任何新增玩法。

## 2. 已批准的状态流与界面职责

### 2.1 状态流

- 应用启动于 MENU。游戏循环可以绘制初始画面，但 MENU 不推进模拟或有效战斗时间。
- 点击开始时重置 GameWorld，再执行 MENU → PLAYING。
- Esc 仅在 PLAYING 与 PAUSED 之间切换。对后续状态（例如 LEVEL_UP）不执行暂停切换，因此不能跳过升级流程。
- 暂停界面提供继续和返回主菜单。返回需在页内确认；取消后仍留在 PAUSED，确认后先重置本局再执行 PAUSED → MENU。
- 失焦和标签页隐藏继续沿用 T002 已确认的自动暂停行为；UI 通过状态订阅显示暂停界面。

### 2.2 状态所有权

GameStateManager 是状态迁移的唯一所有者。UIManager 订阅状态并呈现相应界面，通过 Game 暴露的操作入口请求开始、暂停、继续或返回菜单。UIManager 不直接调用 GameWorld.reset，也不自行改写状态字段。

UIManager 负责 DOM 的创建/绑定、界面显示、键盘与按钮交互、HUD 快照呈现，以及订阅和事件监听的清理。CanvasRenderer 继续负责高频画面绘制；DOM 负责菜单、说明、HUD 和对话框。

## 3. HUD 数据模型与快照

### 3.1 唯一数据来源

- Player 持有玩家生命、等级、当前经验和装备状态。初始值由玩家配置提供：生命 100/100、等级 1、经验 0、装备脉冲枪。
- GameWorld 持有本局击杀数，初始为 0。
- GameClock 是存活时间的唯一来源。
- 运行期声音偏好独立于战局数据，默认开启；本任务不读写 localStorage。

重置 GameWorld 时，玩家属性、装备、本局击杀数和 GameClock 一并恢复初始值。Player.reset 的职责随玩家属性扩展；后续战斗任务必须更新这些相同的数据源，不得另建 HUD 专用计数。

### 3.2 只读快照接口

GameWorld 提供 HUD 快照接口，Game 对 UI 暴露只读转发。快照至少包括：

- 当前生命、最大生命；
- 当前经验、等级；
- 已装备武器 ID 列表；
- 本局击杀数；
- GameClock 的有效存活秒数。

返回对象及其中的集合使用防修改副本。UI 只读取快照，并将稳定武器 ID 映射为显示名称。初始 HUD 显示 100/100、0 经验、等级 1、00:00、0 击杀和脉冲枪。后续 T007、T008、T009、T010、T013 分别把真实战斗结果接入这些来源。

快照不要求 T005 提前实现经验阈值、升级或武器行为。HUD 显示经验数值；升级进度语义仍由 T010 的等级系统负责。

## 4. 界面结构与交互

### 4.1 DOM 与 Canvas

在现有 #app 中叠放 DOM UI 容器，Canvas 保持地图和角色绘制。UI 采用语义化标题、区域、按钮和对话框；颜色沿用现有深蓝底色和青蓝强调色。主视觉素材、动画与额外战斗反馈仍归 T017。

### 4.2 主菜单与帮助

主菜单展示游戏标题、“开始游戏”、“操作说明”和声音开关。操作说明至少列出当前已实现的 WASD/方向键移动和 Esc 暂停；不宣称尚未实现的攻击、升级等功能可用。帮助面板提供返回主菜单的按钮。

声音开关反映运行期的开启/关闭偏好，并更新自己的可访问名称或状态。由于 T005 不存在音源，该状态当前不产生可听效果；T018 接入音频，T019 再接入持久化。

### 4.3 战斗 HUD 与暂停

PLAYING 时显示生命、经验、等级、有效存活时间、击杀数和装备武器；其他状态隐藏战斗 HUD。状态变化时菜单、帮助和暂停界面互斥显示。

HUD 避开画面中心，并在窄窗口下允许换行。仅当展示值变化时更新对应 DOM 内容，避免逐帧写入相同值。暂停返回主菜单使用页内确认对话框，明确确认与取消操作。

## 5. 生命周期、错误处理与测试

UIManager 有 start/stop 生命周期。停止时解除状态订阅、键盘监听和所有 DOM 事件监听，避免重复启动造成重复响应。入口缺少预期的 Canvas 或 UI 容器时，给出可读错误并停止启动，不静默显示空白页面。

测试沿用现有 Vitest，不安装 DOM 测试库、不增加项目依赖：

- 单元测试状态初始值、允许/拒绝的迁移，包括 PAUSED → MENU。
- 单元测试 HUD 快照初始值、数据变化、运行时间读取、返回菜单/重新开始后的重置和防修改行为。
- 测试声音开关状态及 UI 显示映射、HUD 格式化与只在值变化时更新。
- 浏览器检查标题菜单、开始游戏、帮助开关、声音开关、Esc 暂停/继续、返回确认取消/确认、移动与 HUD 实际值。

在敌人、伤害、经验系统尚未完成的 T005 阶段，浏览器只能验证生命、经验和击杀的初始真实值及计时器变化；非零战斗数据的端到端更新由相应后续任务覆盖。不可将这项限制描述为动态战斗 HUD 已通过验证。

## 6. 需求映射与验收

| 需求 | T005 交付 |
|---|---|
| FR-001 主菜单 | 标题、开始、操作说明、声音开关 |
| FR-014 暂停 | Esc 暂停/继续、暂停冻结、确认返回菜单 |
| FR-015 HUD | 生命、经验、等级、时间、击杀、装备武器均来自真实快照 |
| NFR-005 模块职责 | UI 只呈现状态；Canvas 与 DOM 分工；游戏模型拥有数据 |

验收要求：页面加载先显示菜单且不自动推进时间；开始后角色可操作；Esc 暂停后时间停止，再次操作可继续；返回菜单取消保持暂停，确认会清理本局并回到 MENU；重新开始展示初始状态；HUD 使用 GameWorld/Player/GameClock 数据源，不含 UI 固定假数据；声音开关在本次页面运行期内正确反映其状态。

## 7. 风险与后续责任

- T005 只能验证 HUD 的初始数据与时钟，不可独立验证未交付的击杀、伤害或经验战斗链路。T007–T010、T013 接入后须增加相应集成或浏览器回归。
- 运行期声音偏好尚不持久化，声音开关尚未连接音频输出；这是 T018/T019 的明确后续责任，不算 T005 的音频验收。
- T016 的正式胜败/结算重开流程尚未接入。本任务的返回菜单只负责清理现有本局状态，并为未来数据字段留出一致的 reset 扩展点。
- SRS 未授权的玩法与背景音乐均不属于本设计范围。
