# T010 设计规格：经验阈值、等级与连续升级队列

## 审批与决策状态

用户于 2026-10-12 授权持续完成剩余 T010–T021，开发期间不再逐项询问设计确认。本规格按已批准 SRS 工作；对未定义但实现必需的经验表示方式，采用最小且与“当前等级阈值、保留多余经验、逐次升级”一致的方案，并记录于 D-027。不得借此改变已确认敌人、武器或升级玩法。

## 1. 目标与范围

实现 T010 的经验进度换算、等级递增、超额经验保留、多级待处理选择队列，以及进入/退出 `LEVEL_UP` 的冻结状态。T010 提供稳定的领域接口供 T011 升级选择界面逐项消费队列；候选池、卡片 UI、升级效果均不在本任务实现。

## 2. 权威规则与明确解释

- 每个等级 `L` 升至 `L + 1` 需要 `6 + 4 × (L - 1)` 经验，等级从 1 开始。
- `player.exp` 表示**当前等级进度余量**。每跨过一级即扣除该级阈值，立即将 `player.level` 增加 1；剩余经验继续对照新等级阈值计算，任何余量不丢失。
- 每跨过一个阈值，增加一个待处理升级选择。一次经验入账可连续跨过多级；所有等级和余量在同一固定步内结算，待选队列按升级顺序逐项处理。
- `LEVEL_UP` 表示至少有一项待选。第一项待选产生后，在触发它的固定模拟步结束时进入该状态并冻结后续模拟；不能以 Escape、暂停/继续或失焦行为跳过。T011 每完成一个合法选择消费一项；队列非空则保持 `LEVEL_UP`，清空后才返回 `PLAYING`。
- 本级阈值、等级和待选计数只属于当前战局；重开回到等级 1、经验 0、待选数 0。没有 SRS 规定的玩家等级上限，本任务不另设玩法上限。

### 2.1 固定步边界

`GameWorld` 在本步完成玩家/敌人/武器更新、死亡结算、经验晶体拾取后处理等级阈值；随后推进本步战局时钟和步数，再转换到 `LEVEL_UP`。这样阈值触发的固定步完整结算一次，下一步开始前冻结。`GameLoop` 现有的状态检查会在同帧停止后续补算步并清空 accumulator。

## 3. 组件职责与接口

### 3.1 `LevelSystem`

- 只管理 `player.level`、`player.exp` 的阈值结算与 `pendingLevelUps` 队列；不读 DOM、不抽取候选、不改升级属性。
- 集中提供冻结配置 `baseExperience: 6`、`experienceStepPerLevel: 4` 和纯函数 `getExperienceToNextLevel(level)`。
- `processExperience() -> number` 反复消费已满足阈值、递增等级并返回本次新入队数；未达到阈值时玩家进度不变。
- `pendingLevelUps` 只读；`completePendingLevelUp() -> boolean` 仅在 `LEVEL_UP` 且队列非空时消费一项。剩余项大于 0 时留在 `LEVEL_UP`；清空后请求 `GameStateManager.completeLevelUp()` 返回 `PLAYING`。无效调用返回 `false` 且不改状态。
- `reset()` 清零待选队列。它不自行重置 Player；`GameWorld.reset()` 同时通过既有 Player 重置恢复等级与经验。

### 3.2 `GameStateManager` / `GameWorld` / HUD

- 新增受控迁移：`PLAYING → LEVEL_UP`、`LEVEL_UP → PLAYING`；既有 `MENU`、`PAUSED` 路径保持原样。`pause()`、`resume()` 与普通 Escape 不允许离开 `LEVEL_UP`。
- `GameWorld` 在 `ExperienceSystem.update()` 后调用 `LevelSystem.processExperience()`；本固定步推进时钟后，有新待选项时从 `PLAYING` 进入 `LEVEL_UP`。状态非 `PLAYING` 时既有入口停止模拟。
- `GameWorld.reset()` 清空经验晶体后重置 LevelSystem；玩家现有 reset 将 `level/exp` 恢复为初值。
- 现有只读 HUD 快照继续将 `experience` 作为当前等级余量；增加只读 `pendingLevelUps` 供 T011 描述连续待选序列，不改变 HUD 现有经验、等级显示逻辑。
- T010 暂不呈现升级卡片。T011 会在该冻结状态显示选择 UI 并消费队列；T010 与 T011 连续开发完成前，浏览器端触发等级时可能只有逻辑状态而没有选择界面，此阶段只以自动化状态测试验收，不作为可发布体验。

## 4. 错误处理、边界与非目标

- 等级必须是正安全整数；经验必须为非负有限数；非法经验/等级状态不进行静默钳制。
- 阈值边界使用 `exp >= requirement`；恰好达到时升级，严格低于时不升级。
- 一次入账跨越多级时按当前等级逐级扣除，并计算每一级不同的阈值；重置、无待选消费、重复消费不会重复奖励或错误恢复状态。
- 不新增经验乘数、敌人掉落值、等级封顶、卡片概率、效果数值或 UI；不安装依赖。
- 升级奖励的百分比叠加规则属于 T012 的 D-012，不在 T010 中实现。

## 5. 测试与验收

- `getExperienceToNextLevel`: 等级 1/2/3 分别得到 6/10/14；非法等级拒绝。
- 阈值前一微小单位、恰好达到、溢出保留与多级一次跨越；每级使用正确递增阈值且待选数精确。
- `LEVEL_UP` 的合法迁移、阻止 Escape/pause/resume 越过、一次选择后继续保持、最后一项选择后恢复 `PLAYING`。
- GameWorld 集成：晶体拾取获得经验后同一步结算等级，触发步时钟只前进一步，之后世界/时钟冻结；多项队列在选择完成前不恢复；reset 后状态清洁。
- 回归现有状态、循环、经验晶体、HUD 和重开测试。浏览器完整等级选择流由紧随的 T011 实现后统一验收。
