# T012 设计规格：六类升级效果与属性模型

## 状态与依据

用户已授权从 T010 连续完成至 T021，期间不再逐项询问。本文以 SRS 的六类升级及数值为基线；D-012 的待确认项按项目已有建议和本次持续实施授权，采用对基础值线性叠加并保留内部浮点精度的实现规则。T012 实际应用 UP-01、UP-02、UP-03、UP-05、UP-06；UP-04 等级与解锁数据由 T011/T012 提供，轨道刃实体和攻击行为仍归 T013。

## 1. 目标与边界

选择升级卡片后，升级必须真实影响本局状态：火力强化提升所有武器使用的伤害倍率；极速装填提高脉冲枪攻击频率；多重脉冲增加脉冲枪弹丸；机动优化提高玩家移动速度；纳米装甲提高最大生命并恢复生命。效果不得修改共享基础配置，达到 SRS 等级上限后不再提供候选。

本任务不实现轨道刃的移动、碰撞、视觉或独立攻击冷却，也不改变敌人、Boss、波次、经验阈值或已确认升级数值。T013 会读取 `orbitalBladeLevel`，并使用相同的全武器伤害倍率。

## 2. 统一加成公式与数值

- D-012：百分比升级按基础值线性叠加：`effective = base × (1 + perLevelBonus × level)`。各升级使用各自基础值和配置的每级百分比，不进行逐级乘法复利。
- 内部伤害、速度和攻击间隔保留 IEEE-754 计算精度，不为表现提前取整；生命升级的配置增量为整数 20。UI 本任务不新增属性面板或舍入显示。
- UP-01：伤害倍率 `1 + 0.15 × level`，五级时为 1.75；脉冲枪基础伤害 20 对应 35。该统一倍率保留给 T013 轨道刃使用。
- UP-02：脉冲枪频率倍率 `1 + 0.12 × level`，应用间隔为 `baseFireInterval / frequencyMultiplier`。基础 1.25 发/秒，五级为 2 发/秒（间隔 0.5 秒）。已经开始倒计时的冷却仍代表绝对剩余秒数；效果影响下一次攻击后的冷却。
- UP-03：总弹丸数为 `1 + level`，最高三枚。多弹丸共用射程内最近目标的瞄准方向，沿方向对称散开，不改变射程、弹速、单发基础生命周期或每枚弹丸的伤害倍率。
- D-033：相邻弹丸的角度间隔首轮配置为 12 度；以瞄准方向为中心等距排列，二枚时为 ±6 度，三枚时为 −12/0/+12 度。该间隔是可调的首轮技术参数，不是升级数值变更；若后续调整，需记录试玩依据。
- UP-05：移动速度倍率 `1 + 0.08 × level`，五级时基础 220 变为 308 世界像素/秒；从玩家构造时的基础速度计算，不反复乘当前速度。
- UP-06：每级将本局 `maxHp` 增加 20，并将当前 `hp` 增加 20、钳制到新的生命上限；五级后基础最大生命 100 变为 200。新局必须恢复 `hp/maxHp` 到基础 100/100。
- UP-04：选择等级只表示轨道刃解锁/强化层数。T012 的只读升级属性快照暴露该等级给后续武器系统；不提前将轨道刃加入已装备武器列表。

## 3. 架构与数据归属

### 3.1 集中配置与效果快照

- 新增冻结的 `UPGRADE_EFFECT_CONFIG`，以 `UP-01` 至 `UP-06` 为键集中记录每级效果参数；既有 `UPGRADE_CONFIG` 仍是显示名称、描述和等级上限的唯一来源。
- 配置字段固定为：`UP-01.damageBonusPerLevel: 0.15`、`UP-02.pulseGunFireRateBonusPerLevel: 0.12`、`UP-03.extraProjectilesPerLevel: 1`、`UP-04.exposesOrbitalBladeLevel: true`、`UP-05.moveSpeedBonusPerLevel: 0.08`、`UP-06.maxHpIncreasePerLevel: 20` 与 `UP-06.healPerLevel: 20`。配置数字必须有限且符合非负/正值范围，不能从名称/描述字符串解析效果。
- 新增 `UpgradeEffectSystem`，读取 `UpgradeSystem` 的只读等级快照，纯计算冻结效果快照：`damageMultiplier`、`pulseGunFireRateMultiplier`、`pulseGunProjectileCount`、`moveSpeedMultiplier`、`orbitalBladeLevel`。等级越界、缺少配置、非有限或无效参数必须快速拒绝，不得部分修改状态。
- 选择普通升级后，GameWorld 将已验证的选择结果交给 `UpgradeEffectSystem`；纳米装甲按新上限增血，机动优化从 `Player.baseMoveSpeed` 派生当前 `moveSpeed`，其它效果通过冻结效果快照供战斗系统读取。满血恢复兜底仍由 T011 `UpgradeSystem` 按原规则处理。
- `Player.reset()` 恢复其基础 `moveSpeed`、生命和其它基础状态；`GameWorld.reset()` 清除升级等级/快照，重新建立全中性倍率。配置和选择快照均只读。

### 3.2 脉冲枪与 GameWorld

- `WeaponSystem.update()` 接收可选的只读效果快照；未提供时使用全中性倍率，以保持独立测试和既有调用兼容。
- 伤害在创建 `Projectile` 时使用 `config.damage × damageMultiplier`，确保在途弹丸不因之后升级而改变已有伤害。
- 射击间隔在发射时使用 `config.fireIntervalSeconds / pulseGunFireRateMultiplier`；一次有效射击按 `pulseGunProjectileCount` 创建对应数量的弹丸，所有弹丸拥有唯一 ID。
- GameWorld 将当前效果快照传给脉冲枪系统，并对外只读提供该快照，以便 T013 消费共用伤害倍率和轨道刃等级。
- `GameWorld.reset()` 之后，冷却、弹丸、等级和玩家速度/生命均按已有每局重置规则回到基础值；不更改 `PULSE_GUN_CONFIG`、`PLAYER_CONFIG` 或其他共享配置。

## 4. 生命周期与错误处理

- 只在有效选择成功后更新效果；非法候选、非 `LEVEL_UP` 状态或无待选项仍由既有 GameWorld/T011 路径拒绝，不得改变等级、玩家数值、冷却或队列。
- 效果倍率按等级快照重算，不递增修改共享配置，也不对当前倍率反复相乘；重复选择不同顺序应得相同结果。
- 升级在 `LEVEL_UP` 冻结期间生效，选择完成后第一帧移动/射击即读取更新后的状态；冻结期间没有模拟步，也不推进既有武器冷却。
- 重开清空所有本局效果；敌人/投射物 ID 不复用规则和本任务无关，不重置系统级计数器。

## 5. 验收

- 单测验证配置冻结与 SRS 参数、D-012 公式的 0/1/最大等级边界、等级上限拒绝/快照稳定、UP-04 等级可供消费。
- 玩家/效果系统测试验证 UP-05 从基础速度派生且重置恢复、UP-06 生命上限增长/受伤后治疗/不超上限/连续升级，以及所有统计不修改共享配置。
- 武器测试验证升级前后伤害、攻击冷却、弹丸数、对称角度、唯一 ID、最高三枚和默认中性参数；在途弹丸伤害保持发射时快照。
- GameWorld 集成测试验证选择调用真实效果、LEVEL_UP 队列冻结/逐项消费、所有升级效果对下一步生效以及重开清零。
- 运行完整 Vitest、Vite 生产构建和 `git diff --check`；不安装依赖。浏览器能自然触发升级时，验证脉冲枪伤害/频率/多弹与 Nano Armor HUD；若自然升级不可达，则如实记录未验证，不添加正式调试入口。
