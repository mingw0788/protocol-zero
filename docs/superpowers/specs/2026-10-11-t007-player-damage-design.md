# T007 玩家受伤与碰撞设计规格

**状态：** 对话设计各节及正式规格均已获用户通过（2026-10-12）。
**日期：** 2026-10-11
**范围：** T007 玩家/敌人接触碰撞、生命伤害、无敌时间、初步死亡信号及死亡后的战局冻结。

## 1. 目标与约束

让 T006 的普通感染体可以通过接触伤害玩家，并可靠地实现生命钳制、受击无敌和一次性死亡通知。T007 不增加或调整已确认数值：玩家最大/初始生命 100、玩家半径 16 世界像素、EN-01 接触伤害 10、受击无敌时间 0.6 秒。可调数值集中在配置中。

遵循现有 1/60 秒固定模拟步长；无敌计时只随 `PLAYING` 的有效模拟时间递减。暂停、菜单和失焦自动暂停期间不推进计时。当前 Canvas/HUD 已读取玩家真实生命，因此不新增假状态或专用 HUD 数据。

## 2. 模块职责

- `CollisionSystem({ player, enemies })` 要求玩家有有限坐标和正半径、`enemies` 为数组；缺少必要引用时抛 `TypeError`，非法数字抛 `RangeError`。它持有两者的只读引用；`getPlayerContacts()` 按世界坐标检测玩家与敌人的圆形重叠，距离平方小于或等于两半径之和的平方时视为接触。它只返回仍存活且生命值大于 0 的敌人，不修改位置或实体状态。
- `DamageSystem({ player, invulnerabilitySeconds = PLAYER_CONFIG.invulnerabilitySeconds })` 管理玩家无敌计时与接触伤害。无敌时长必须为正的有限数，否则抛 `RangeError`。`update(deltaSeconds)` 只递减计时，delta 必须是非负有限数，否则抛 `RangeError`；`applyContactDamage(contacts)` 要求数组输入，在计时到 0 且玩家存活时才接受伤害，伤害后将计时设为配置的 0.6 秒，并返回 `{ damaged, killed, damage }`。未命中、玩家已死亡、无敌中或最大接触伤害为 0 时，结果为 `{ damaged: false, killed: false, damage: 0 }`；有效命中时 `damaged` 为真，`damage` 为实际伤害，`killed` 表示本次是否将生命降至 0。生命值钳制在 `[0, maxHp]`；受击期间后续接触既不扣血，也不刷新计时。
- `Player` 增加每局独立的 `alive` 与 `invulnerabilityRemaining` 运行字段。`Player.reset()` 将生命恢复至 `maxHp`，存活恢复为 `true`，无敌剩余时间清零。
- `PlayerSystem.clearInput()` 封装清空玩家移动输入。
- `GameWorld` 负责在固定模拟步中调用系统、清空死亡时的移动输入并发送一次死亡事件。`subscribePlayerDeath(listener)` 注册单一事件订阅，返回取消订阅函数。系统不直接改游戏状态、DOM 或渲染对象。

预期代码边界：新增 `src/systems/CollisionSystem.js` 和 `src/systems/DamageSystem.js`；修改 `src/config/playerConfig.js`、`src/entities/Player.js`、`src/systems/PlayerSystem.js` 与 `src/core/GameWorld.js`。不修改 `GameStateManager`、`Game` 或 UI；正式失败状态由 T016 接入。

## 3. 碰撞与同时接触规则

碰撞在玩家移动、Camera 跟随及敌人追踪之后检测。实体按圆形半径计算；接触检查仅触发伤害，不阻挡移动、不推开敌人，也不施加击退。

如果多只敌人在同一模拟步接触玩家，且玩家无敌计时已经结束，该步只应用一笔伤害，取接触敌人中最大的 `contactDamage`。伤害不求和，也不依赖敌人数组顺序。该规则沿用每次受击触发 0.6 秒保护的约定；对当前仅有的 EN-01，伤害仍为 10。

每个有效模拟步先以 `deltaSeconds` 递减无敌计时并钳制到 0，再进行本步碰撞检测。因此无敌时间到达 0.6 秒边界时，持续重叠的敌人可以在该边界造成下一次伤害。`DamageSystem` 对非有限或负值的 delta 抛出 `RangeError`，对非正或非有限的无敌时长抛出 `RangeError`；Player 和 Enemy 的位置、半径及接触伤害沿用实体构造器的有限值/正值验证，避免 NaN 污染状态。

## 4. 死亡、事件与更新时序

每个 `PLAYING` 模拟步按以下次序处理 T007 行为：

1. 若世界已死亡冻结，则不再推进任何战局系统并返回未更新。
2. `DamageSystem.update(deltaSeconds)` 递减玩家无敌计时。
3. 更新玩家移动和 Camera。
4. 清理失效敌人，更新生成系统，再推进存活敌人。
5. `CollisionSystem.getPlayerContacts()` 检测玩家接触；`DamageSystem.applyContactDamage(contacts)` 应用至多一笔伤害，并返回是否击杀玩家。
6. 完成本固定步：推进战局时钟和模拟步计数。
7. 若本步首次令玩家生命归零，清除移动输入、锁定死亡事件并同步通知订阅者。

玩家生命到 0 时设为 0 并把 `alive` 置为 `false`。致死的固定模拟步正常完成；之后 `GameWorld.update()` 不再推进玩家、敌人、生成或时钟。T007 暂不增加 `DEFEAT` 状态：当前状态机保留 `PLAYING`，现有 HUD 显示 0 生命，玩家仍可使用 Esc 和现有暂停/返回菜单路径。若恢复已死亡的局面，战局继续冻结。

`GameWorld.subscribePlayerDeath(listener)` 提供单一事件订阅点，校验 `listener` 为函数并返回取消订阅函数。事件同步触发一次/每局，payload 为冻结对象 `{ elapsedSeconds }`，其中时间包含致死的完整固定步。重复接触和死亡冻结期间不重复通知。注册在死亡之后的监听器不接收历史事件。`GameWorld.reset()` 保留订阅关系、清除本局死亡锁；新局再次死亡时可再通知一次。T016 将在游戏初始化时订阅该事件，并负责转入正式失败状态及显示结算 UI。

## 5. 配置与数据规则

- `PLAYER_CONFIG` 增加 `invulnerabilitySeconds: 0.6`，集中保存规则值；不得在碰撞、伤害、核心循环各自硬编码副本。
- EN-01 继续使用 T006 配置中的 `contactDamage: 10`；T007 不新增敌人类型或波次参数。
- 伤害仅能降低生命；本任务不实现治疗接口、护盾、击退、受击闪烁或粒子效果。视觉受击反馈仍属 T017。
- 每个 `GameWorld`/Player 实例的生命、存活和无敌计时彼此隔离，不修改全局配置。

## 6. 验收与测试

### 单元测试

- 圆形恰好相切触发接触，略微分离不触发；不同半径使用世界坐标。
- 死亡或生命不大于 0 的敌人被排除；检测过程不修改玩家/敌人。
- 单只接触伤害正确；生命不小于 0；无敌时间为正时不扣血且不刷新时间；到达 0.6 秒边界时可再次受击。
- 同步接触只造成最高单次接触伤害，不累加且不依赖数组顺序。
- 归零时玩家只发生一次存活到死亡的转换；非法时间/几何或伤害参数不能污染数值。

### 战局集成测试

- 仅在 `PLAYING` 更新计时和碰撞；`MENU`、`PAUSED` 与失焦暂停冻结无敌时间和生命。
- 碰撞使用玩家与敌人本步移动后的坐标；HUD 快照及时显示真实生命。
- 致死模拟步计入时钟，死亡通知一次；后续模拟步不再推进任何战局系统并清空输入。
- `reset()` 恢复玩家属性、重新开放战局更新；订阅关系保留，下一局仍只通知一次。
- 回归 T002–T006 的时钟、状态、输入、摄像机、生成与 HUD 行为。

### 浏览器与交付验证

- 从标题菜单开局，等待感染体接近；检查 HUD 扣血、无敌间隔和死亡后的冻结。
- 检查死亡后可以暂停、确认返回菜单并重开，生命恢复为 100，控制台没有新增错误。
- 运行 `npm test` 与 `npm run build`；不安装依赖。没有实际执行的兼容性或压力测试必须明确标为未验证。
