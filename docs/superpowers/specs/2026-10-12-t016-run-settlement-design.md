# T016 终局胜败、结算与重开设计

**日期：** 2026-10-12  
**依据：** `docs/requirements.md` §3.1、FR-013、`docs/architecture.md` §4、D-009、T016 任务要求  
**状态：** 已按连续开发授权实施；交付与独立审查见 `docs/task-report-T016.md`

## 意图与范围

补齐从主菜单开始、进入战局、达成胜利或失败、查看结算、重开或返回主菜单的闭环。保留现有玩法和数值：Boss 在 270 秒生成；胜利需有效战局时间至少 300 秒且 Boss 已死亡；Boss 在 300 秒后仍存活时继续战斗；玩家 HP 小于等于 0 时失败；同一固定步内死亡优先。终局显示击杀数和有效存活时间。T016 不新增敌人、升级或 Boss 玩法，不持久化最高纪录（归 T019）。

## 状态与结算职责

- `GameStateManager` 添加 `VICTORY`、`DEFEAT` 两个终态，并提供只允许从本局进行态进入终态的单次结算迁移。终态不允许暂停或返回 PLAYING。
- `GameWorld.update` 在既有固定步内完成伤害、Boss/武器/经验、死亡收尾及有效时钟推进后，计算一次终局：先看玩家死亡，再看 `elapsedSeconds >= 300 && bossSnapshot?.alive === false`。先前击败 Boss 的战局在 300 秒边界正常胜利；越过边界时 Boss 仍活着则继续，不因超出 300 秒而自动胜利。
- 终局判定早于发起新的 LEVEL_UP 选择；一个同时达到升级与胜利条件的存活固定步进入 VICTORY，不会留下待选升级面板。玩家死亡时不发起升级，且 DEFEAT 优先。
- GameWorld 提供冻结终局快照 `{ outcome, killCount, elapsedSeconds }`；快照在终局冻结，重置本局时清空。此数据只读，不由 UI 自行计算。
- 有效时间为 GameClock 完成致死步后的值，格式按现有 HUD 的 `MM:SS` 整秒向下显示。重开将经 `GameWorld.reset()` 复用当前对象并完整清本局状态，然后转入 PLAYING；这符合现有 loop/world 依赖关系和 SRS 的清零语义，不需拆换仍被 GameLoop 引用的对象。

## UI 与流程

- 增加一个语义清晰的结算对话面板，胜利/失败标题不同，展示击杀数和存活时间，并提供“再来一局”“返回主菜单”。仅 VICTORY/DEFEAT 显示。
- “再来一局”仅在终态可用：清理一次本局后直接开始新局；“返回主菜单”清理本局再进入 MENU。菜单、暂停、升级、终局之间不得出现背景模拟推进。
- UI 管理器只读 Game 的终局快照并调用受状态校验的动作；状态切换时更新面板和焦点。原音效开关状态与 UI 运行结构不被 reset 清除。
- 不在 T016 写入本地成绩，保留给 T019。

## 验证

自动化覆盖合法/非法终态迁移、Boss 在 300 秒前死亡但等待到界、边界固定步胜利、300 秒后击败仍存活 Boss、死亡优先、连续更新不重复结算、LEVEL_UP 冲突、终局冻结和快照、键鼠界面动作、连续重开无残留/菜单返回清理。运行全套 Vitest、生产构建和 diff 检查，并用浏览器实际交互验证结算/重开/返回流程及控制台。
