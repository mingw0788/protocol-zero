# T011 设计规格：升级候选与三选一界面

## 状态与设计依据

用户已授权在 T010–T021 全部完成前持续推进，并要求期间不再询问。本文遵守现有 SRS 的升级种类、等级上限、重复规则和暂停要求；候选池抽样方式、无剩余候选时的行为细节等未明确部分，按最小且可复现的方案记录到 D-030/D-031。T011 只负责候选生成、选择确认与待选队列消费；真实属性效果仍归 T012，轨道刃攻击归 T013。

## 1. 目标与范围

让真实 `LEVEL_UP` 状态出现可操作的升级选择界面：每个待选升级展示最多三个不同的合法候选；玩家确认其中一个后记入该局升级等级，并消费一项待选。若队列仍有升级，则立即展示一组新选项并保持冻结；最后一项选择后回到 `PLAYING`。

实现集中配置、候选抽样、等级上限过滤、选择校验、全满级时的生命恢复兜底，以及 DOM / Canvas 游戏的状态呈现。T011 不实现数值加成公式和升级对 Player/武器属性的实际影响，候选选择只记录等级变化；这些效果由 T012 接入。T011 不实现轨道刃攻击实体与动画（T013），也不改动确认过的玩法数值。

## 2. SRS 规则

| ID | 选项 | 描述 | 最高等级 |
|---|---|---|---:|
| UP-01 | 火力强化 | 全武器基础伤害 +15% | 5 |
| UP-02 | 极速装填 | 脉冲枪攻击速度 +12% | 5 |
| UP-03 | 多重脉冲 | 每次攻击额外增加 1 枚弹丸 | 2 |
| UP-04 | 轨道刃模块 | 首次解锁，之后强化轨道刃效果 | 5 |
| UP-05 | 机动优化 | 移动速度 +8% | 5 |
| UP-06 | 纳米装甲 | 最大生命 +20 并恢复 20 生命，不超过新上限 | 5 |

- 一个抽样结果不能重复；候选必须当前可升级且未达到对应等级上限。
- 合法选项少于三个时，只展示所有剩余合法选项，不填充重复卡片。
- 六项均满级时，提供可重复的「纳米维护」兜底选项，将当前生命恢复至生命上限；它不增加任何升级等级，也不提高生命上限。
- 每次选择消费一项待选。仍有待选时不恢复模拟，并为下一项重新抽样；待选清空后返回 `PLAYING`。

## 3. 未明示规则的最小裁定

- **D-030 候选抽样：** 对所有当前合法选项使用等权重、无放回抽样，展示 `min(3, 合法选项数)` 个；注入随机函数供确定性测试，不新增权重或稀有度。
- **D-031 选择确认：** 激活升级卡片本身就是确认；支持鼠标、Enter 和 Space，不增加二次确认。`LEVEL_UP` 下 Escape 不关闭界面、不消费队列、不恢复模拟；键盘焦点限制在对话框内。最后一项选择后关闭卡片并按既有状态订阅恢复战斗焦点。
- 满级兜底在每次选择后仍立即适用；若六项已满而队列还有多项，则每次都重新提供生命恢复。
- 选项随机数必须是有限 `[0, 1)` 值；注入值不合法时抛 `RangeError`，不生成部分候选。

## 4. 架构与数据归属

### 4.1 配置与 `UpgradeSystem`

- 新增冻结配置，集中存放六种 ID、名称、描述和最高等级；不在 UI、GameWorld 或测试辅助逻辑中复制等级上限。
- 新增 `UpgradeSystem({ player, random, upgrades })`。它维护当前局各升级等级与当前展示候选；默认使用 SRS 六项配置，可注入随机源/配置以测试一至两项及全满级边界。
- `prepareChoices()` 只在首次进入一次待选或完成选择后调用，生成新的冻结候选快照 `{ id, name, description, currentLevel, targetLevel, maxLevel, repeatable }`。不从渲染帧重新抽样。
- `select(choiceId)` 只接受当前快照中的候选。普通候选递增该项等级并返回冻结的选择结果 `{ id, previousLevel, level, maxLevel }`，供 T012 接入效果；生命兜底返回独立的恢复类型结果，设置 `player.hp = player.maxHp` 且不增级。选择成功后清除已展示候选。
- `reset()` 清除所有升级等级和候选；只读 getter 返回不可变升级等级/候选快照。

### 4.2 `GameWorld` 与 `Game`

- `GameWorld` 持有一个 `UpgradeSystem`；与普通敌人生成使用独立随机源，避免候选抽样改变敌人生成的随机序列。
- 当本步 `LevelSystem.processExperience()` 新增待选时，先准备首组候选，再进入 `LEVEL_UP`，使同步状态订阅者可立即读取候选。
- `GameWorld.chooseUpgrade(id)` 仅在 `LEVEL_UP` 且待选数大于零时接受合法候选；随后消费一项。队列未空时准备下一组，队列清空时清理候选。无效 ID、无效状态不改等级、生命、队列或状态。
- `Game.getUpgradeChoices()` 提供冻结只读快照；`Game.chooseUpgrade(id)` 作为界面操作入口委托给 GameWorld。UI 不直接更改 Player、UpgradeSystem、LevelSystem 或状态机。
- `GameWorld.reset()` 在 T010 已定义的 `LEVEL_UP` 拒绝规则不变；合法重置同时清空升级等级与候选。

### 4.3 DOM 界面

- 在 UIManager 现有状态面板中新增升级选择 panel 和最多三个静态、可访问的按钮卡片；避免每次帧更新创建 DOM 节点。
- 进入 `LEVEL_UP` 时隐藏菜单、HUD、暂停面板并展示 `role="dialog"`, `aria-modal="true"` 的升级面板；标题、剩余选择数和卡片名称/等级/描述来自只读快照，剩余次数通过 `aria-live="polite"` 宣告。合法选项不足三项时隐藏未使用卡片。
- 激活卡片调用 `Game.chooseUpgrade(id)`；成功后刷新下一组卡片。如果消费最后一项，状态订阅关闭面板并恢复游戏焦点。
- 初次打开及每组新候选显示后将焦点放到第一张卡片。Tab / Shift+Tab 在可见选项间循环；Escape 被阻止并保持选择状态。选项数至少为一（候选或兜底），所以总有可聚焦按钮。
- CSS 延续现有赛博朋克深色面板、青色高亮和窄屏容器布局；卡片面板可滚动，不影响固定 Canvas 游戏视口。

## 5. 固定步、生命周期与错误处理

- 状态在现有 `LEVEL_UP` 转换中保持冻结；选择过程不推进 GameClock、GameWorld、敌人、投射物或经验晶体。
- 超额一次升级由 T010 的队列保存；T011 每次只消费一个。下一候选必须在 UI 同步刷新前准备好，避免中间出现空面板或恢复一步模拟。
- 每局的升级等级与候选通过 `GameWorld.reset()` 清除；全局配置冻结、对象/系统引用稳定、事件订阅不因重开重复注册。
- 非法候选和非 LEVEL_UP 选择返回 `false`，所有领域状态不变；候选配置重复 ID、无效上限或随机源类型错误在构造时拒绝。
- 全局 `GameStateManager` 仍是状态权威；T011 选择不暴露普通暂停/返回菜单绕过路径。

## 6. 验收与验证

- `UpgradeSystem`：配置冻结；抽到三个互异合法候选；满级项过滤；合法池 1/2 项时返回准确数量；全满时反复返回生命兜底；无效/过期 ID 拒绝；无效 RNG 不产生部分状态；reset 清理。
- `GameWorld` 集成：经验拾取进入真实 `LEVEL_UP` 并已有首组候选；每个选择只消费一项；连续待选生成新选择且状态/时钟保持冻结；最后一项恢复 `PLAYING`；无效选择不改变状态；新局从初始等级重新抽样。
- UI 单测：状态显隐、候选文本、按钮调用、少于三项隐藏、Escape / 键盘焦点行为、重复 start/stop 的监听清理。
- 浏览器：通过实际菜单开始游戏并自然触发升级选择，检查卡片可见/可操作、Escape 不能跳过、连续选择停住模拟且最后选择恢复、Canvas/UI 无控制台错误。T011 不要求完成人为加速经验的开发作弊入口；若完整触发耗时超过浏览器会话限额则如实记为未验证，并由 UI 单测与集成测试覆盖。
- 运行现有全套 Vitest 和生产构建；不安装依赖。

## 7. T011 边界与后续接口

- T011 交付候选展示、合法选择、选择等级记录和健康兜底，不把候选名称或等级渲染当成属性效果已生效。
- T012 读取 `UpgradeSystem` 的选择结果/等级，实现真实属性与脉冲枪修正，并处理 D-012 加成叠加公式；T013 实现轨道刃的实际攻击。
- 设计与开发期间不变更 SRS 给定的升级类别、数值和等级上限。
