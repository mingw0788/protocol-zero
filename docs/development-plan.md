# Codex 分阶段开发计划（Implementation Plan）

| 元数据 | 内容 |
|---|---|
| 文档编号 | PZ-PLAN-001 |
| 项目 | 《零号协议：失控之城》/ Protocol Zero |
| 版本 | 1.0 |
| 依赖 | `docs/requirements.md`、`docs/architecture.md` |
| 当前状态 | T000–T003 已完成；后续任务需用户逐项指定 |
| 实施目标 | 完成 V1 网页版 5 分钟完整生存游戏 |

## 1. 开发总原则

1. **先审查，再实施。** 用户第一次在 Codex 中执行的是 T000，仅做文档审查。
2. **任务独立：** 每次只执行用户明确指定的任务，不自动执行后继任务。
3. **完整循环：** Implementation → Tests → Review → Fix → Git Commit → Next Task。
4. **变更可追踪：** 代码、测试、文档和 Git 提交对应一个任务范围。
5. **真实验证：** 未执行测试标“未验证”；未提交标“未提交”，禁止编造测试记录和提交哈希。
6. **功能边界：** 只开发 SRS V1 范围，其他创意追加到后续 backlog。
7. **技能优先：** 先实现可玩核心，后替换像素素材与音效，再做细节优化。
8. **质量门禁：** 上一阶段验收未通过前，禁止标记下一阶段已完成。

## 3. 任务详细清单

### M0：准备与框架

#### T000 — 需求基线与任务审查

- **类型：** 文档审查；**前置：** 无。
- **实现边界：** 不写任何游戏源代码、不安装依赖、不初始化 Vite。
- **步骤：** 阅读 `AGENTS.md`、SRS、SDD、PLAN；逐条核对功能需求与任务覆盖；检查关键边界（270 秒 Boss、300 秒胜利、重复死亡/掉落、连续升级、Esc 暂停、角色重开）；检查架构与任务依赖；输出风险及待确认问题。
- **产物：** 文档审查报告、FR/NFR 追踪矩阵、风险列表、T001 准备清单；必要时更新 `docs/decisions.md` 和 `docs/task-status.md`。
- **验收：** FR-001～FR-018 与 NFR-001～NFR-010 都有任务映射；文档无关键未处理冲突；未开发游戏代码。

#### T001 — 工程初始化

- **前置：** T000 完成，审查问题已处理。
- **步骤：** 建立 Vite + 原生 JavaScript 工程；初始化 Canvas 页面、必要的 `src` 基础目录和入口；创建 Git 忽略项、开发/构建/测试命令，安装 Vitest；补充 README 运行说明。
- **测试：** 开发服务器显示启动页面；构建成功；最小测试脚本运行；工作区可追踪。
- **验收：** 仅存在最低限度工程骨架，不提前实现玩家和敌人。

#### T002 — 主循环、时钟与状态机

- **前置：** T001。
- **步骤：** 实现 GameLoop 固定步长、GameClock、GameStateManager、GameWorld 最小可用结构；支持 MENU/PLAYING/PAUSED。窗口失焦或标签页隐藏时自动暂停，回到页面后须手动继续且不补算失焦时间；每帧最多补算 5 个 `1/60` 秒步，超额时丢弃整步积压、保留不足一步的余量，暂停/失焦时清空余量。
- **测试：** 有效时间只在 PLAYING 递增；PAUSED 完全冻结逻辑；多帧率模拟的游戏时间一致；每帧最多补算 5 步且正确保留小于一步的余量；失焦恢复不补算后台时间且不自动继续。
- **验收：** 正确启动/暂停/继续；单元测试通过。

**M0 质量门禁：** 运行入口与测试命令可用，状态和时间管理可靠。

### M1：可操作原型

#### T003 — 地图、坐标与摄像机

- **前置：** T002。
- **步骤：** 创建 2400×1350 世界地图、基础像素网格背景；摄像机跟随目标，支持世界/屏幕坐标转换与地图边界。使用 1280×720 逻辑视口；Canvas 后备位图随 CSS 尺寸和 DPR 调整，保持等比缩放并居中留边。
- **测试：** 摄像机不越界；坐标转换测试；调整窗口不非等比拉伸；DPR 和窗口尺寸变化正确更新 Canvas；地图背景、网格和边界正常绘制。
- **验收：** 能看到可移动视口，不出现黑屏、位移错乱。

#### T004 — ZERO 玩家移动

- **前置：** T003。
- **步骤：** 创建玩家实体；WASD/方向键输入；归一化斜向速度；220px/s 初始移动；玩家碰撞半径、地图边界；占位角色绘制。
- **测试：** 水平/竖直/斜向等速；按键松开与失焦正确；玩家无法出界；帧率变化不改变速度。
- **验收：** 能在浏览器中流畅操作角色移动。

#### T005 — 主菜单与基础 HUD

- **前置：** T004。
- **步骤：** HTML/CSS 主菜单、操作帮助、开始与暂停；HUD 显示真实生命、经验、等级、存活时间、击杀数；UI 与游戏数据接口分离。
- **测试：** 按钮可用；Esc 暂停/继续；菜单/战斗状态切换正常；HUD 不依赖固定假数据。
- **验收：** 可从菜单进入可操作场景并安全暂停。

**M1 质量门禁：** 实际浏览器中主菜单→控制角色→暂停/继续成功；试玩评价基本移动手感。

### M2：基础战斗

#### T006 — 基础敌人系统

- **前置：** T004（实施顺序在 T005 之后）。
- **步骤：** 敌人实体与配置；首先实现普通感染体；敌人追踪；摄像机视口外合法生成；实体更新与删除；普通敌人上限 100。
- **测试：** AI 朝玩家移动；生成位置合法且远离玩家；数量不超过上限；死亡实体可清理。
- **验收：** 场景中敌人稳定生成追踪，无无限增殖。

#### T007 — 玩家伤害与死亡

- **前置：** T006。
- **步骤：** 玩家/敌人圆形碰撞；接触伤害；0.6 秒受击无敌；生命下限/上限；初步死亡事件与输入冻结。
- **测试：** 受击扣血正确；短时间重叠不反复扣血；生命归零不能继续正常战斗。
- **验收：** 可以被敌人打败，死亡事件只发生一次。

#### T008 — 脉冲枪自动攻击

- **前置：** T006、T007。
- **步骤：** 武器抽象/初始脉冲枪；射程内最近目标选取；攻击冷却；投射物移动及生命周期；弹丸命中伤害；敌人死亡事件；击杀计数。
- **测试：** 没目标时不开火；自动选最近合法目标；命中扣血；子弹生命周期结束清理；死亡只计击杀一次。
- **验收：** 无需按键便能攻击、消灭普通敌人。

#### T009 — 经验晶体掉落与拾取

- **前置：** T008。
- **步骤：** Enemy 死亡发放经验晶体；可视拾取范围；拾取后增加经验；重复掉落/拾取保护；实体生命周期清理。
- **测试：** 击杀产生正确掉落；接触拾取一次；经验无负值；掉落不会无限累积已失效实例。
- **验收：** 已完成“移动→射击→击杀→拾取”闭环。

**M2 质量门禁：** 浏览器实际试玩，检查走位/自动瞄准/敌人反馈的可玩性。

### M3：随机成长

#### T010 — 经验阈值和连续升级

- **前置：** T009。
- **步骤：** 经验公式 `6 + 4×(当前等级−1)`；等级递增；保留多余经验；待处理升级队列或等效逻辑；触发 LEVEL_UP，冻结游戏。
- **测试：** 边界值、一次拾取升多级、经验余量、升级期间游戏时间不增长。
- **验收：** 经验达到阈值时正确升级，不丢失升级次数。

#### T011 — 升级三选一卡片

- **前置：** T010。
- **步骤：** 升级池抽样；三个不同合法选项；达到等级上限的过滤；不足三个的处理；全满级生命恢复兜底；升级弹窗/确认流程；Esc 不可跳过。
- **测试：** 候选去重、满级过滤、合法选择与无效选择拒绝；暂停恢复；连续升级选择。
- **验收：** 三选一卡片可操作，选后生效并恢复战斗。

#### T012 — 六类升级及属性模型

- **前置：** T011。
- **步骤：** 配置 UP-01～UP-06；实现火力、装填、多弹丸、机动、纳米装甲；UP-04 先完成数据接口与合法候选（实际武器由 T013 对接）；建立统一百分比增益叠加规则。
- **测试：** 升级对真实数值有作用；等级上限生效；血量不超上限；配置不被污染；多重脉冲最多三枚总弹丸。
- **验收：** 除实际轨道刃攻击外，各类型增益均可验证。**本任务不能将尚未实现的轨道刃功能标为已完成。**

#### T013 — 轨道刃解锁与武器协作

- **前置：** T012。
- **步骤：** 添加第二武器轨道刃；随玩家旋转；与敌人碰撞；每目标命中冷却；通过 UP-04 第一次解锁、之后强化；UI 武器图标与状态同步。
- **测试：** 初次获得/重复升级正确；能伤害敌人；同目标不能逐帧无限扣血；脉冲枪与轨道刃共存正常。
- **验收：** 所有六类升级全部实装且真实有效。

**M3 质量门禁：** 实际试玩验证随机升级与两武器的体验，至少比较两种升级组合。

### M4：完整战局

#### T014 — 三种敌人和波次变化

- **前置：** T013。
- **步骤：** 在已存在普通感染体上添加迅捷猎犬、重装机甲；按 0～270 秒分段变化生成权重和数量；控制普通敌人活跃上限；展示敌人差异。
- **测试：** 各类数值符合配置；波次与有效战斗时钟一致；暂停不推进波次；不非法生成。
- **验收：** 敌群逐渐有压力变化，三种敌人行为可区分。

#### T015 — 机械暴君 T-01

- **前置：** T014。
- **步骤：** Boss 数据与绘制、追踪、蓄力预警（≥0.7 秒）、冲锋、受伤、死亡；270 秒单次生成；Boss 独立血条。
- **测试：** 269.x 秒不出现、达到 270 秒出现一次；冲锋预警符合要求；伤害死亡事件不重复；暂停期间 Boss 不动。
- **验收：** 可实际战斗并击败 Boss。

#### T016 — 完整胜败与结算、重开

- **前置：** T015。
- **步骤：** 300 秒且 Boss 死亡胜利，否则继续战斗；玩家死亡失败；同周期死亡优先；胜负 UI、击杀/存活时间结算；从结算重新开始/回菜单；创建新 GameWorld。
- **测试：** 不到 300 秒即杀 Boss 仍等至 300 秒；超过 300 秒仍活着的 Boss 被击败后胜利；玩家死亡优先；重复重开无残留。
- **验收：** 从菜单到完整结束再重开的闭环成立。

**M4 质量门禁：** 至少完成一整局人工测试，记录胜败条件与任何体验问题。

### M5：美术、音效、存档与发布

#### T017 — 原创像素美术、动画与 UI 打磨

- **前置：** T016。
- **步骤：** 替换占位素材为原创或已获使用许可的像素美术；统一深蓝/青色/红色/紫色/金色调；玩家移动/受击、敌人死亡动画；战斗粒子和 Boss 蓄力预警；完善菜单及 HUD。
- **测试：** 玩家/敌人清楚可辨；技能特效不会遮蔽危险；静态资源路径有效；缺资源时显示兜底。
- **验收：** V1 达到一致赛博朋克像素风，有稳定视觉反馈。

#### T018 — 音频系统与设置

- **前置：** T016。
- **步骤：** Web Audio API 或适当浏览器音频能力；攻击/受伤/死亡/升级/结算音效，背景音乐；开关/音量；处理自动播放限制与资源失败降级。
- **测试：** 有交互后音频可以播放；静音设置有效；攻击密集时声音不过载；音频失败不阻断游戏。
- **验收：** 音频功能稳定，菜单中有可用控制。

#### T019 — 本地成绩与设置

#### T020 — 回归、性能与稳定性

- **前置：** T017、T018、T019。
- **步骤：** 完整执行单元/集成测试；Chrome 与 Edge 人工试玩；对象生命周期检查；大量敌人压力测试；发现瓶颈后有针对性优化；整理 Bug 清单。
- **测试：** FR-001～FR-018 逐条回归，NFR-001～NFR-010 检查记录；完整 5 分钟以上战局；多次重开；暂停/失焦/窗口缩放。
- **验收：** 无阻断性缺陷；实际记录性能数据；未通过的项目写清楚原因，不掩盖问题。

#### T021 — 构建、部署与交付

- **前置：** T020。
- **步骤：** 生产构建；完成 `README.md` 操作与运行说明；整理已知限制、素材许可证和后续计划；部署到可用静态托管；线上实际验证；创建 V1.0 版本标签。
- **测试：** 生产构建成功；发布网址可以打开；线上可开始/通关/重开；无开发服务器依赖；Git 标签指向已验证提交。
- **验收：** **V1.0 Complete**，可以向他人分享试玩。

## 5. Git 与质量门禁

### 5.1 提交规范

- 建议每项任务通过后提交一次，提交消息示例：`feat: implement T004 player movement`、`test: cover T010 level thresholds`、`docs: finish T000 review`。
- 不提交 `node_modules`、本地构建缓存、临时视频和不相关修改。
- 尊重用户未提交的变更，先检查差异再提交。
- 为 M0～M5 记录可复盘的测试结果；T021 再打 `v1.0.0` 标签。

### 5.2 阻断性问题

- 游戏黑屏、无法开局、逻辑时间错误、玩家无法移动、胜败判定错误、重开崩溃、丢失经验或无法升级：必须阻止对应任务标为完成。
- 次要美术瑕疵或额外音效建议可记录 backlog，前提是没有破坏既定阶段验收。

### 5.3 任务完成统一输出

```text
Task ID：Txxx
执行状态：完成 / 部分完成 / 阻塞
本次实现：
修改文件：
自动化测试：命令、运行结果（未执行需注明）
人工浏览器测试：操作、结果（未执行需注明）
Review：问题与改进
Fix：已修复/未修复
Git Commit：哈希或未提交原因
风险与遗留：
下一任务：Tyyy（仅建议，不自动开始）
```

更新 `docs/task-status.md`；只有证据充分的任务才能被打勾。T000 审查完成、满足必要条件后才允许启动 T001。

## 6. 项目风险和应对

| 风险 | 后果 | 控制措施 |
|---|---|---|
| V1 功能不断增加 | 延迟交付 | 用 SRS 锁定范围，后续版本放 backlog |
| AI 代码一次生成过多 | 难测试与维护 | 每轮只做 Txxx，逐项测试和提交 |
| 过多对象引起卡顿 | 体验明显下降 | 数量上限、生命周期清理、性能分析 |
| 游戏模块耦合 | 追加武器/敌人困难 | 数据配置和渲染分离，统一事件语义 |
| 先做美术忽略玩法 | 花时长却不好玩 | M2/M3/M4 先试玩，T017 再打磨 |
| 虚报测试/提交状态 | 无法确认质量 | 明确实测证据与 Git 哈希 |
| 浏览器音频限制 | 音效不工作 | 用户操作后启动音频，可静音降级 |
