# V1 人工玩法验收补测

**复核日期：** 2026-10-13

**范围：** 仅补齐 M3、M4 人工玩法质量门禁；不改变已确认的玩法、数值或版本范围。

## 当前结论

T000–T021 的实现、任务级测试、生产构建与静态发布均已有记录。仍有两项计划门禁未闭环：

| 门禁 | 计划要求 | 现有证据 | 状态 |
|---|---|---|---|
| M3 成长系统 | 实际试玩随机升级和两种武器，并至少比较两种升级组合 | T020 自然键盘战局在 HUD 00:32、16 击杀时失败，未到升级门槛；T013 的轨道刃浏览器验证为受控升级选择 | 待人工补测 |
| M4 完整战局 | 人工完成至少一整局，记录胜败条件和体验问题 | T016 自动化/受控浏览器验证了胜败边界；T020/T021 未记录自然完整战局 | 待人工补测 |

这是验收证据缺口，不是已确认的软件缺陷。此前的自动化测试、受控夹具和探索性自动按键均不能替代上述人工门禁。已确认的战斗参数保持不变；若补测持续显示升级难以自然触发或战局压力失衡，应先提交带有试玩数据的平衡建议，再按项目决策流程处理。

开发计划规定前一阶段门禁未通过时不能标记后续阶段整体完成。因此 M5/T021 的静态发布交付事实保留，但在 M3/M4 关闭前，整体 V1 验收状态为部分完成；`v1.0.0` 标记的是已发布构建，不是人工玩法门禁证书。

## M3 补测步骤

1. 使用当前发布构建，在目标桌面浏览器从标题菜单自然开局；不改时钟、生成、伤害、生命、掉落或碰撞参数，不注入实体或升级。
2. 通过移动、闪避和自动攻击收集经验，记录首次升级时间、玩家生命、等级、经验与击杀数。
3. 至少完成两次可比较的自然升级选择体验。记录每次可见候选、实际选择、选择前后武器/HUD/战斗感受；组合应不同，且能观察脉冲枪与轨道刃的实际作用。若单局未出现足够升级，可重开再试并保留失败记录。
4. 记录升级是否易理解、选择是否可辨、升级效果是否在后续战斗中可感知，以及是否存在被敌群/拾取节奏压制到无法体验的情况。

## M4 补测步骤

1. 从标题菜单开始一局自然战斗，按正常操作游玩至游戏自然进入胜利或失败结算。
2. 不用调试器、时间注入或受控 Boss/HP 夹具。可以记录多局尝试；至少一局须到达自然结算，方可关闭本门禁。
3. 记录结局类型、有效战斗时间、击杀数、等级/经验、生命、升级选择、Boss 出场及击败结果（如有），并记录导致失败或胜利的关键过程和体验问题。

## 关闭条件

- **M3：** 至少两种不同自然升级组合有逐局记录，且能说明两种武器和所选升级在实战中的可辨效果；无记录的受控 UI 夹具不计入。
- **M4：** 至少一局从菜单自然进行到胜利或失败结算，记录结果和体验问题；只推进模拟时钟或注入 Boss/生命状态不计入。
- 完成后更新 `docs/task-status.md`、本文件及 README 的门禁状态，并链接试玩记录。试玩若暴露玩法平衡问题，先记录建议，不直接改动已确认规则。
